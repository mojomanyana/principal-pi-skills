## Review: Pagination function

The core bug is an **off-by-one error** in the slice endpoint.

### The bug

```python
return items[start : start + size - 1]   # ❌ drops the last element
```

Python slices use `[start:stop)` — `stop` is **exclusive**. To return `size` elements, the stop index should be `start + size`:

```python
return items[start : start + size]        # ✅ correct
```

**Example:** `size=10, n=0`  
- `start = 0`, slice becomes `items[0:9]` → returns 9 items instead of 10.
- Every page is short by one element.

### Other issues (less critical but worth noting)

* **Edge case:** If `size` is 0 or negative, division by zero isn't a concern here, but `start + size - 1` could produce a nonsense slice. Consider validating: `if size <= 0: raise ValueError` or similar.
* **Unguarded negative `n`:** `start = -1 * 10 = -10` would slice from the end of the list — probably not intended. Guard with `if n < 0` or document that page numbers are 0-based.
* **Empty/gap pages:** If `start >= len(items)`, Python returns `[]` — this is fine and arguably correct, but worth a docstring note.

### Suggested fix

```python
def page(items, size, n):
    """Return page `n` (0-based) of `size` items from `items`."""
    if size <= 0:
        raise ValueError("size must be > 0")
    if n < 0:
        raise ValueError("n must be >= 0")
    start = n * size
    return items[start : start + size]
```
