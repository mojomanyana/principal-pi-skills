## Bug: `parseCount` accepts suffixes like `3x`
Reproduction: `node --input-type=module -e "import { parseCount } from './parse.mjs'; console.log(parseCount('3x'))"` → printed `3` in disposable workspace.
Isolated to: `parse.mjs` using `Number.parseInt(value, 10)`.
Hypotheses tested: `parseInt` parses numeric prefixes and ignores trailing junk → confirmed: `parseCount('3x')` returned `3`.
Boundary evidence: bad value first appears at `parse.mjs:1`; implementation does not validate whole input before conversion.
Wait condition: not applicable
Root cause: confirmed; `Number.parseInt` accepts partial decimal prefixes, violating `SPEC.md` PARSE-1 requiring an entire nonempty ASCII digit string and safe integer.
Fix: proved in disposable workspace only, not applied to caller tree:

```js
export function parseCount(value) {
  if (typeof value !== 'string' || !/^[0-9]+$/.test(value)) {
    throw new TypeError('invalid count');
  }

  const count = Number(value);
  if (!Number.isSafeInteger(count)) {
    throw new TypeError('invalid count');
  }

  return count;
}
```
