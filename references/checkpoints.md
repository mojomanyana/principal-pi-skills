# Save delivery and recall its evidence

## Save

For an authorized project handoff, use the selected Bookie project. Write a short outcome, the important remaining limitation and the next action. Two or three sentences usually suffice. Use an open choice only for a decision the user owns.

Attach the sources for the claims the next session will need. For a design decision, identify the actual consultation or label the reasoning as inline. For a check, retain its result receipt or exact report and revision. For research, retain the original brief reference and check the passage that supports the claim. Preserve a refusal or partial result as such. A task can have just one of these sources.

When `bookie_remember` supports `includeEvidence`, request the relevant categories (`decision`, `validation`, `research`) from the current work. If Bookie offers multiple matching calls, select the relevant returned IDs with `evidenceCallIds`. An observed command call can locate a result; its identity alone does not establish what passed. Only attach sources that belong to this task and are authorized for this project's memory. Keep protected source contents with their owner.

With an older Bookie, use its structured checkpoint's Evidence section when the project and save route are already configured. Otherwise use the available routine note with a concise, permitted locator and identify any missing linkage. Read back the exact save receipt and confirm which sources were included. After an uncertain write, inspect that receipt or known target before creating another note.

## Recall

Find the matching project checkpoint and read its exact entry. For a question about a result, open the relevant source through its authorized owner. For a registered Scout source, use the checkpoint's registration ID with `bookie_reference_read` and `part:"brief"` if available. Opening the body needs current disclosure permission. A command locator can identify a historical call even when its output is unavailable. Attribute what was observed to the source you actually read. If it differs from the checkpoint, report the discrepancy and which source supports the answer.

Keep conclusions within the observed cases. For a paged source, a matching passage can support a narrow claim. To say a finding is absent from the whole source, read through the last page or say which part you inspected. If the source is missing, changed or inaccessible in this session, report what the checkpoint recorded and what remains unverified. A recall-only request uses existing records and leaves work and memory untouched.

For a delivery check, use its returned checkTask and copy the endpoint ID, expected value, journey and any counterexample into the verification request. For independent review, copy the delivery review criterion ID and requirement into the prepared review. Principal links observed matching receipts during work and checks them against the current files on recall. Use the evidence action to select between competing receipts.

In a handoff, distinguish results reopened this turn, outcomes recorded only in the checkpoint, and sources currently unavailable. A file check establishes presence, and a saved test script describes a check. Report a runtime outcome as verified only when its applicable result is available.
