# Research during a Principal task

Use public research when a specific fact could change the task. `architect` may need a platform
constraint or migration prerequisite, `build` a documented API behavior that installed code leaves
unclear, and `review` or `debug` an authoritative library/runtime specification. Routine work
proceeds directly.

1. Use applicable evidence already available within the task's permissions. A role needing more
   returns one focused question, the decision it affects, and any work that can proceed.
2. When `pi-scout-research` is installed and public research is authorized, call `scout_research`
   with the focused question, relevant versions, and any known official URLs. Keep private project
   data out of the request.
3. Read the relevant original passage. For a paged saved brief, follow `nextOffset` from the
   current response until you find the relevant finding and its limits. A search hit alone is
   insufficient; return the supported finding, citation, and material gaps.
4. If a source or Scout is unavailable, carry the gap on the dependent conclusion and continue
   independent work. Reuse authorized evidence across roles to avoid repeating research.
